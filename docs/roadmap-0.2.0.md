# kakigori 0.2.0 roadmap

v0.1.0 ships an honest asymmetry: with ground-truth boxes the graph +
serializer stack reaches 93.2% / 80.4% pitch/rhythm, but the fully
detection-driven path (`infer-omr`) sits at 29.0% / 23.3% (median 33%,
best files 90–93%). The gap is not detection recall (notes detect fine)
— it is the edge model meeting detection noise it never saw, plus
structure classes the serializer depends on detecting poorly. 0.2.0
attacks that gap on a deliberately narrowed problem first.

**Status 2026-10-21.** Stages A–C were redone on a rebuilt stack:
musicset data with varied renders, a ReGLA detector with 12× fewer
parameters, multi-label decoding and a 640×896 canvas.

| | now | July (ConvNeXt, fixed renders) |
| --- | --- | --- |
| detector mAP@.50 (80 classes, multi-label) | 0.795 | — (not measured this way) |
| GT boxes + predicted edges | 94.4 / 90.8 | 93.8 / 89.5 |
| detection-driven kern | 53.4 / 47.5, median 53.6 | 49.6 / 44.2, median 53.8 |

The two columns come from different renders of the same scores, so they
show the trend, not a strict A/B.

Stage D is next. Details, evaluation caveats and the bugs found are in
[lite-results-2026-10.md](lite-results-2026-10.md).

## The LITE track (proving ground)

A small, clean, focused pipeline where every 0.2.0 idea is cheap to
iterate and honestly measurable, before scaling back to the full corpus.

**Corpus** (`data/train-lite` 9.5k scores / `data/validation-lite` 500,
filtered from the 254k-score MusicXML corpus with `filter-mxl --lite
--max-pages 2`): exactly one part, single staff or piano grand staff,
1–2 pages. The lite gates also reject tablature/percussion, broken
sources whose accidentals exist only gesturally (`<alter>` without any
printed `<accidental>` and no key signature), corrupted layouts that
render as unreadable smears (no-line-break sources: >15 measures per
system; single-measure sources: >40 notes per measure), and staves
carrying more than one voice (a MuseScore visual-editor artifact that
also breaks the lite track's linear temporal chains).
Since 2026-10-18 both sets are built with musicset (`--profile varied`:
engraving sampled per score), so July numbers are not directly
comparable with later ones.

**Classes** (`conf-lite/`, 99 = 109 − 10): removed `autogenerated`,
`syl`, `verse`, `label`, `labelAbbr`, `pgHead`, `dir`, `tempo`, `harm`
(unusable without harmony understanding), and `ledgerLines` (annotated
in bulk boxes — confounded, never learned: AP 0.11 at 132k instances).
Note: with `syl`/`verse` gone the `synchronization_text` role is empty —
lite graphs have no class-4 (sync-text) edges; the 6-class edge head
keeps the slot unused.

**Input resolution — revisited after the backbone change.** With the DINOv3
ConvNeXt backbone, both 960px input and `scale_ranges` changes measured
worse (see `docs/experiments/vision/`). With ReGLA, the picture changed:

- **640×896 wins.** A page-shaped 640×896 canvas gives 1.4× the linear
  resolution of the square 640 letterbox. It is the current detector:
  80-class mAP@.50 0.795 vs 0.731, and the weak classes gain most.
- **Keep each class on its level.** When resolution changes, scale the
  ranges by the area factor (×1.96 here). With unscaled ranges, glyphs
  that grow past a boundary move to another head.
- **448×640** matches square 640 at 0.70× the pixels, so it is the
  speed option.
- **Stage 4** (stride 32) is deprioritised.

## Architecture: joint detection + graph loss

The original phase-3 idea, properly understood: train ONE model with a
**double loss** — the detection loss (heatmap + size regression, per
page) plus the edge-classification loss summed **per system**:

```
L = L_det(page) + λ · Σ_systems L_edges(system)
```

Why this beats the shipped curriculum:
- The detection loss anchors the shared backbone+neck, so full
  unfreezing is safe — no more detector drift (the reason phase 3 was
  shelved and the two-neck deployment exists).
- One neck, one model, one checkpoint — the deployment wart disappears.
- The model produces detections at training time, enabling the real
  prize below.

With ReGLA (2026-10) the joint model keeps its detection quality: 0.800
vs 0.794 standalone, with stems and barlines at 0.99. The thin-vertical
collapse of the July ConvNeXt joint runs is gone. The joint model and the
two-model phase-2 pipeline are within noise of each other on
detection-driven kern.

## Train the GNN on its own detections

Box-jitter (σ=1.5 px) was a proxy; it does not simulate misses, false
positives, or class confusion. The matching module makes the real thing
trainable:

1. Hungarian-match GT nodes ↔ detections (class + IoU cost).
2. Transfer GT edge labels through matched pairs; edges touching
   unmatched detections become class 0 (none); unmatched GT nodes drop.
3. Curriculum: GT boxes → jittered GT → own detections (per-epoch mix).

This also yields the missing evaluation primitive: per-class
recall/precision of the *pipeline* rather than mAP.

## Denoising front-end (real-scan bridge)

The scanner-augmentation pipeline already generates perfect training
pairs (clean render ↔ degraded). Train a small image-to-image model
(UNet) degraded→clean and apply it at inference so the detector always
sees its training distribution. Validation MUST include real scans
(e.g. IMSLP piano pages) — the augmentations are a model of scan noise,
not the distribution itself. Independent of everything else; can land
any time.
